# AI 助手授权状态合并需求说明

本文定义 AI 助手页面中「主机命令 · 本次会话未授权」与「授权级别控制」合并后的
功能需求与交互要点。**只描述用户看到什么、能做什么、系统必须遵守什么规则，不描述
接口与代码实现。**

## 1. 背景与问题

当前「02 授权范围」里有两套并列的授权入口：

1. **主机命令**：一个开关，状态写作「本次会话 · 未授权 / 已授权」；
2. **虚拟机内**：一张限时票据，需要单独选择授权级别（只读 / 受限变更 / 运维授权）、
   时长、目录与服务，再点一次「签发授权」。

同一轮排查往往既要在主机上跑命令，又要进虚拟机看日志。用户因此要授权两次、
理解两套状态、在两个地方分别撤销；两处状态不一致时（例如主机已授权、虚拟机未
授权），页面也没有一句话说清「现在到底能做什么」。

## 2. 设计目标

1. **一次确认，两条通道**：用户只做一次授权决定，即可同时开启本次会话需要的主机
   命令与虚拟机内能力，不再分别授权。
2. **一个状态，分层表达**：页面只有一个授权总状态，之下再分通道、范围、时限，
   用户一眼能看出「当前能做什么、到什么时候、缺哪一块」。
3. **一个入口，按状态变化**：未授权、部分授权、已授权、即将到期、已过期都从同一
   个主入口完成必要操作，不要求用户先撤销再重新授权。
4. **不破坏既有边界**：主机授权仍然是会话级；虚拟机仍然是限时票据；改系统的命令
   仍然逐条审批；不允许静默提权或自动续期。

### 非目标

- 不把「授权」变成「免审批」：合并的是授权入口与状态展示，不是逐条审批。
- 不把主机授权改成持久化，也不把虚拟机票据延长到会话结束。
- 不自动替用户选择「运维授权」，也不在用户不知情时把只读升级为可写。

## 3. 统一授权模型

### 3.0 概念层级

合并后仍然是「一个总状态 + 多条通道 + 各自范围」，不是把所有信息压成一个开关：

| 层级 | 回答的问题 | 示例 |
| --- | --- | --- |
| 总状态 | 本次会话现在能不能做 | 已授权 / 部分授权 / 已过期 |
| 通道 | 对哪个对象生效 | 主机命令 / 虚拟机内 |
| 级别 | 最多能做到哪一步 | 只读排查 / 受限变更 / 运维授权 |
| 范围 | 具体能碰什么 | 可读目录、可写目录、可重启服务 |
| 有效期 | 到什么时候 | 本次会话 / 剩余 28:14 |
| 审批 | 每一步怎么放行 | 只读直接执行；变更逐条批准 |

总状态是派生结果，不能反过来替代通道与有效期；级别只描述能力上限，不等于自动
放行；范围与审批始终独立展示。

### 3.1 两条通道，一个总状态

| 通道 | 作用对象 | 生命周期 | 能力 |
| --- | --- | --- | --- |
| 主机命令 | 当前目标主机 | **本次会话** | 只读诊断命令直接执行；受限变更及以上，会改动系统的命令可提议、逐条批准 |
| 虚拟机内 | 当前目标对应的 VM | **限时票据**（15 / 30 / 60 / 120 分钟，受策略上限约束） | 只读 / 受限变更 / 运维授权三档；变更逐条批准 |

两条通道的生命周期不同，这是必须保留的安全边界，不能为了「统一」而抹平：

- 总状态可以显示「已授权」，但必须同时标出「主机：本次会话」「虚拟机：剩余 28:14」。
- 虚拟机票据到期后，总状态自动变为「部分授权」，主机命令仍然可用；不能因为票据
  到期就把主机授权一起清掉。
- 撤销也一样：可以只撤销虚拟机、只撤销主机，或「撤销全部」；后两者必须是明确选择。

### 3.2 统一授权级别

对外只保留三个级别，同时约束两条通道：主机命令在只读级别不提供写提议，在受限
变更/运维下行为一致；虚拟机内按三档收窄。级别只决定「能不能提议/执行哪一类动作」，**
不改变逐条审批**。

| 级别 | 主机命令 | 虚拟机内 | 适用场景 |
| --- | --- | --- | --- |
| 只读排查 | **仅只读命令**；不提供写命令提议 | 只读目录、只读命令 | 看日志、查进程、定位故障 |
| 受限变更 | 只读命令直接执行；写命令可提议，逐条批准 | 在勾选的目录 / 服务内变更，逐条批准 | 改配置、重启指定服务 |
| 运维授权 | 同「受限变更」；主机没有更高级别 | 整机 shell：可装软件、改任意配置；逐条批准，不可回滚动作仍拦截 | 补依赖、修复坏掉的配置 |

要点：

- **级别是显式选择**，默认「只读排查」；「运维授权」必须由用户主动选中，并展示
  风险说明。
- **只读级别不出现写提议**：AI 只能跑只读命令；如果排查中确实需要改动，必须提示
  用户把级别提升到「受限变更」，不能自行提议写命令。这是收紧，不是放宽。
- 主机命令在「受限变更」与「运维授权」下行为一致；即使选择运维授权，主机上的写
  命令仍然逐条审批，不会因为级别更高而自动执行。
- 级别只在授权时固化；会话中途不能静默升级，必须重新走一次「调整授权」。
- 策略与权限可以**收紧**级别（例如 `prod` 标签禁写、管理员关闭运维授权、用户没有
  `ai.vm.write`）；不能放宽，也不能自动降级后继续执行——必须让用户看到原因。

### 3.3 通道可用性

统一面板根据目标与权限决定哪些通道可用：

| 情况 | 主机命令 | 虚拟机内 | 页面表现 |
| --- | --- | --- | --- |
| 目标有受管主机 + 合格 VM | 可用 | 可用 | 默认两条都勾选 |
| 目标只有受管主机，没有 VM | 可用 | 不可用 | 虚拟机行置灰并说明「未关联虚拟机」 |
| 目标只有 VM（纯虚拟机会话） | 不可用 | 可用 | 主机行置灰并说明「未登记为受管主机」 |
| 用户无 `ai.exec` | 不可用 | 视权限 | 主机行显示「无权限」，不提供绕过 |
| 用户无 `ai.vm.read` | 视权限 | 不可用 | 虚拟机行不显示或置灰 |
| 用户只有 `ai.vm.read` | 视权限 | 仅只读 | 受限变更 / 运维授权选项禁用并说明原因 |
| VM 未运行 / Agent 未响应 | 可用 | 不可用 | 与目标选择规则一致，主操作禁用 |

不可用通道必须给出原因，不能只把开关置灰。

没有虚拟机通道时，级别仍然决定主机能否提议写命令：`只读排查` 与 `受限变更` 可选，
`运维授权` 不可选（没有客户机可运维）；反之只有虚拟机通道时，主机级别不影响页面，
按虚拟机的三档展示。

## 4. 状态展示

### 4.1 层级结构

授权状态按四层展示，从上到下依次收窄：

```
第 1 层  总状态：已授权 / 部分授权 / 未授权 / 已过期 / 策略受限
         一句说明：本次会话能做什么，虚拟机还剩多久
         主操作：授权本次排查 / 补全授权 / 一键续期 / 调整授权
         ─────────────────────────────────────────────
第 2 层  通道状态（两行，固定顺序）
         主机命令   已授权 · 本次会话     [撤销]
         虚拟机内   受限变更 · 28:14     [续期] [撤销]
         ─────────────────────────────────────────────
第 3 层  范围明细（按需展开）
         主机：只读直接执行；受限变更及以上写命令逐条批准
         虚拟机：可读目录 / 可写目录 / 可重启服务 / 动作配额 / 快照 / 策略限制
         ─────────────────────────────────────────────
第 4 层  动作流水与审计（沿用现有「本次会话执行过的操作」，不与状态卡混排）
```

原则：

- **总状态只回答「现在能不能做」**，不替代通道状态；两条通道的生命周期必须在
  第 2 层同时可见。
- **主操作只有一个**。撤销是次操作，且「撤销全部」必须二次确认。
- **状态与权限一致**：没有权限、策略禁用、目标不可用时，主操作显示为禁用并给出
  原因，不能假装可用、点击后才报错。

### 4.2 总状态矩阵

| 主机通道 | 虚拟机通道 | 总状态 | 主操作 |
| --- | --- | --- | --- |
| 未授权 | 未授权 / 无可用 VM | 未授权 | 授权本次排查 |
| 已授权 | 未授权 | 部分授权 · 仅主机命令 | 补全虚拟机授权 |
| 未授权 | 生效中 | 部分授权 · 仅虚拟机 | 补全主机授权 |
| 已授权 | 生效中 | 已授权 · {级别} | 调整授权 |
| 已授权 | 剩余 ≤ 5 分钟 | 已授权 · 即将到期 | 一键续期 |
| 已授权 | 已过期 | 部分授权 · 虚拟机已过期 | 一键续期 |
| 任一 | 策略/权限拒绝 | 策略受限 | 调整授权（禁用不可选项） |
| 目标已切换 | 旧票据不匹配 | 需要重新授权 | 授权本次排查 |

补充规则：

- 总状态里的「级别」取两条通道中**较高**的能力：主机允许写提议即为「受限变更」，
  虚拟机为运维授权则为「运维授权」；只有主机只读 + 虚拟机只读时才是「只读排查」。
  没有虚拟机通道时显示「仅主机命令 · {级别}」。
- 「部分授权」必须用警示色，并明确指出缺哪一条通道，不能只显示「部分」。
- 即将到期的判定固定为「剩余 ≤ 5 分钟」，在倒计时进入该区间时自动切换文案。
- 目标切换后，旧票据仍在服务端生效的，进入第 2 层「其他生效中的授权」列表，
  允许「使用这张」一键绑定，不要求重新签发。

### 4.3 状态卡内容

状态卡自上而下固定包含：

1. 标题：`本次会话授权`；
2. 总状态徽标 + 一句说明；
3. 主操作按钮；
4. 两条通道行（主机 / 虚拟机），每行包含状态、生命周期、能力摘要、次要操作；
5. 可展开的「范围明细」；
6. 其他生效中的授权（如有）。

示例（只读 + 主机命令，虚拟机票据生效中）：

> **本次会话授权**  `已授权 · 只读排查`  
> 主机命令与虚拟机只读均已开启，虚拟机票据剩余 28:14。  
> **主机命令** `已授权 · 本次会话` — 只读命令直接执行；写命令需先提升到受限变更  
> **虚拟机内** `只读 · 28:14` — 可读 /var/log、/etc；动作 3/40  
> `[调整授权]`  `[撤销全部]`

示例（虚拟机票据过期）：

> **本次会话授权**  `部分授权 · 虚拟机已过期`  
> 主机命令仍可用；虚拟机内需要重新授权后才能继续。  
> **主机命令** `已授权 · 本次会话`  
> **虚拟机内** `已过期` — 上次为「受限变更」  
> `[一键续期]`  `[调整授权]`  `[撤销全部]`

## 5. 一步授权交互

主流程只有一条：

```
状态卡（未授权 / 部分授权 / 已到期）
        │ 点击唯一主按钮
        ▼
统一授权面板（级别 + 通道 + 范围 + 时长 + 预览）
        │ 一次确认
        ▼
状态卡更新（主机 + 虚拟机同时生效）
        │ 若上一轮被授权挡下
        ▼
继续执行（沿用既有入口，不重新描述问题）
```

### 5.1 入口

- 唯一的授权入口是状态卡上的主按钮，文案随状态变化：
  - 未授权：`授权本次排查`
  - 部分授权：`补全授权`
  - 即将到期 / 已过期：`一键续期`
  - 已授权：`调整授权`
- 页面上不再保留独立的「主机命令开关」和「签发授权」按钮；原先的开关行为并入
  统一面板中的「作用通道」。
- 主按钮在目标未选择、目标不合格、无任何可用通道时禁用，并在按钮附近说明原因。

### 5.2 统一授权面板

点击主按钮打开**一个**面板（抽屉或对话框，不采用多步向导），内容顺序固定：

1. **授权级别**
   - 三张可选卡片：只读排查 / 受限变更 / 运维授权；
   - 默认选中「只读排查」；
   - 每张卡片显示能力边界、是否需要逐条批准、风险提示；
   - 不可选级别置灰，并写明原因（无权限 / 策略关闭 / 标签禁写 / 目标不支持）。

2. **作用通道**
   - `主机命令`：勾选后本次会话内有效；
   - `虚拟机内`：勾选后按所选时长签发/续期；
   - 默认两条都勾选（可用时）；
   - 不可用通道置灰并说明原因；
   - 至少保留一条通道，否则确认按钮禁用。

3. **虚拟机范围**（仅虚拟机通道且级别为受限变更/运维授权时展开）
   - 可写目录、可重启服务；
   - 运维授权显示整机风险说明；
   - 只读级别隐藏这些字段。

4. **有效时长**（仅虚拟机通道）
   - 15 / 30 / 60 / 120 分钟；
   - 显示策略允许的上限；选择超过上限时就地提示「将按上限 X 分钟签发」，而不是
     确认后才被悄悄截断；
   - 主机通道固定标注「本次会话」，不提供时长选项。

5. **生效预览**
   - 用一句话列出本次确认将发生什么：
     > 将开启：主机命令（本次会话）+ 虚拟机「受限变更」（30 分钟，可写 /etc、可重启 nginx）。
   - 如果该目标已有生效中的票据：
     - 级别相同：提示「将沿用现有票据并重置到期时间」；
     - 级别不同：提供两个明确选项——`使用现有授权` / `撤销并重新签发`；
       不能直接覆盖，也不能等确认后返回冲突错误。

6. **确认**
   - 一个主按钮：`确认授权`（续期场景为 `确认续期`）；
   - 确认后两条通道同时生效，面板关闭，状态卡立即更新；
   - 提示一条合并结果：`已授权：主机命令（本次会话）+ 虚拟机（受限变更，30 分钟）`。

### 5.3 快速授权

为常见的「只想让它开始查」场景提供低摩擦路径：

- 未授权且两条通道都可用时，状态卡主按钮旁提供 `快速授权（只读）`；
- 一次点击即按推荐默认值生效：主机命令开、虚拟机只读、15 分钟、两条通道同时开；
- 生效后状态卡立刻提供 `调整授权`，用户仍可随时升级或缩小范围；
- 「快速授权」不允许直接产生受限变更或运维授权，后两者必须经过统一面板确认。

### 5.4 按需授权与继续执行

AI 在排查中需要主机命令或虚拟机内能力、但当前未授权或级别不足时：

- 对话流给出一条**授权请求卡**，说明「需要什么通道、用来做什么、为什么当前级别不够」，
  而不是直接失败；例如只读级别下需要改配置时，明确提示「需要提升到受限变更」；
- 点击后打开同一个统一授权面板，预选所需通道与最低足够级别；
- 确认成功后，自动继续刚才被挡下的那一步（沿用现有「继续执行」语义），用户不必
  重新描述问题；
- 若用户拒绝，AI 收到明确结果并给出不依赖该能力的替代方案。

### 5.5 续期、调整、撤销

- **续期**：一键沿用上次的级别、范围与通道，只重置虚拟机到期时间；主机通道本来
  就是会话级，不重复授权。续期前展示新的到期时间。
- **调整**：打开统一面板，预填当前授权；确认后一次性应用两条通道的变化。
  - 升级级别：必须显式选择，并展示新增能力与风险；
  - 降级级别：立即收紧；已发出的动作仍按原记录审计，不回滚已完成的变更；
  - 取消某条通道：等同撤销该通道，需在预览里写明。
- **撤销**：
  - 通道行提供单通道撤销；
  - 状态卡提供 `撤销全部`，二次确认；
  - 撤销虚拟机票据时，沿用「同时终止客户机内正在运行的命令（支持时）」的既有
    行为，并如实提示「兼容模式下命令可能自行跑完」；
  - 撤销主机通道只影响后续轮次，不回溯已经执行的命令。

## 6. 必须保持的既有逻辑

合并不能改变以下语义：

1. **主机授权是会话级的**：新建会话、切换目标主机后回到未授权；刷新页面后不恢复。
2. **虚拟机授权是限时票据**：有独立到期时间、动作配额、目录/服务范围、快照与
   回滚记录；到期或撤销后不能继续执行。
3. **变更逐条审批**：授权只决定「能不能提议/执行」，不替代每一次写命令的审批；
   双人审批、风险拦截、不可回滚动作拦截全部不变。
4. **只读级别不提供写提议**：这是合并后对主机通道的收紧——只读级别下 AI 只能跑
   只读命令，写命令必须先把级别提升到「受限变更」。除此之外，主机通道的会话级
   生命周期、逐条审批与撤销语义不变。
5. **默认最小权限**：默认只读；运维授权必须显式选择；策略与角色权限只能收紧。
6. **不静默降级/升级**：级别冲突、策略拒绝、权限不足都必须让用户看见并重新选择，
   不能自动换一个级别继续跑。
7. **审计完整**：一次统一确认产生的主机授权与虚拟机票据必须能关联到同一次操作；
   用户能在「排查记录 / 动作流水」里看出两条通道分别授了什么、到什么时候。
8. **「继续执行」入口**：刚完成授权且上一轮被挡下时，仍然提供明确的继续入口，
   不要求用户重新提问。

## 7. 权限、策略与异常

| 场景 | 页面与交互 |
| --- | --- |
| 无 `ai.exec` | 主机通道置灰，说明「没有主机命令权限」；只保留虚拟机通道（如有） |
| 无 `ai.vm.read` | 虚拟机通道不显示；只保留主机通道 |
| 仅有 `ai.vm.read` | 级别只可选「只读」；受限变更/运维置灰并说明缺 `ai.vm.write` |
| 管理员关闭运维授权 | 「运维授权」置灰，说明由管理员策略关闭 |
| 目标带禁写标签（如 `prod`） | 受限变更/运维不可选，或明确提示只能授予只读；不得静默降级 |
| 策略上限低于所选时长 | 面板内就地显示将被压到上限，确认前可见 |
| 已有不同级别的生效票据 | 预览里二选一：沿用现有 / 撤销并重新签发；一次确认完成 |
| 目标在面板打开期间被切换 | 面板关闭或刷新为目标对应的授权状态；禁止把授权签给旧目标 |
| 票据在面板打开期间到期 | 确认时按新签发处理，展示新的到期时间 |
| 目标关机 / Agent 掉线 | 主操作禁用并说明「目标当前不可用」；不自动撤销已有票据 |
| 用户权限在会话中被收回 | 状态卡显示「权限已变化」，对应通道置灰；后续动作被服务端拒绝 |
| 双人审批生效 | 在状态卡与预览中显示「高危动作需双人审批」；不改变审批流程 |

## 8. 文案与状态标签

| 位置 | 文案 |
| --- | --- |
| 卡片标题 | 本次会话授权 |
| 总状态 | 未授权 / 部分授权 / 已授权 / 已过期 / 策略受限 |
| 主按钮 | 授权本次排查 / 补全授权 / 一键续期 / 调整授权 |
| 快捷按钮 | 快速授权（只读） |
| 通道名 | 主机命令 / 虚拟机内 |
| 生命周期 | 本次会话 / 剩余 mm:ss / 已过期 |
| 级别 | 只读排查 / 受限变更 / 运维授权 |
| 预览 | 将开启：主机命令（本次会话）+ 虚拟机「{级别}」（{时长}，{范围摘要}） |
| 确认 | 确认授权 / 确认续期 |
| 结果 | 已授权：主机命令（本次会话）+ 虚拟机（{级别}，{时长}） |
| 撤销 | 撤销主机命令 / 撤销虚拟机授权 / 撤销全部 |

要求：

- 状态不能只靠颜色区分，必须有文字徽标；
- 「部分授权」必须写出缺哪条通道；
- 「已过期」必须写清是主机还是虚拟机，不能用笼统的「授权失效」；
- 所有禁用选项都要带原因，原因与权限/策略/目标状态一一对应。

## 9. 验收标准

1. **一次确认完成两条通道**：从未授权状态打开统一面板，确认一次后，主机命令与
   虚拟机票据同时生效；用户没有执行第二次授权操作。
2. **状态可独立解读**：只看状态卡就能回答「现在主机能做什么、虚拟机是什么级别、
   还剩多久、缺哪条通道」。
3. **生命周期不混淆**：虚拟机到期后总状态变为「部分授权」，主机命令仍可用；
   一键续期只续虚拟机，不重复开启主机。
4. **切换目标不串授权**：切换目标后状态卡立即反映新目标；旧票据只出现在「其他
   生效中的授权」里，需显式「使用这张」才绑定。
5. **新会话重置主机**：新建会话后主机通道回到未授权；虚拟机票据按既有规则独立
   存在，且能被一键沿用。
6. **无静默提权**：默认只读；运维授权必须显式选择并看到风险说明；策略/权限拒绝
   时选项不可选，不能自动换级别。
7. **只读不碰写**：只读级别下 AI 不出现主机写命令提议，也不提供虚拟机写操作；需要
   变更时只能通过同一面板提升到受限变更或运维授权。
8. **审批不变**：所有会改动系统的命令仍然逐条审批；双人审批与不可回滚拦截不变。
9. **冲突一次解决**：已有不同级别票据时，在面板内完成「沿用 / 撤销并重新签发」
   的选择，不出现确认后才报错的情况。
10. **按需授权可续跑**：AI 因缺授权被挡下时，从对话流打开同一面板，确认后自动
    继续该步骤。
11. **审计可关联**：一次确认产生的主机授权与虚拟机票据能追溯到同一次用户操作；
    两条通道各自的到期时间与范围可查。

## 10. 待确认事项

以下不影响主结构，但需要在评审时拍板：

- 只读级别是否收紧主机写提议：本文默认「只读级别不出现写提议」；若要求严格沿用
  现有「主机开关一开即可提议写命令」的行为，则必须在级别卡片上明说「主机命令不受
  级别限制」，否则「只读」二字会误导用户；
- 「快速授权（只读）」是否默认同时开启两条通道，还是只开启当前任务需要的那条；
- 续期时是否允许顺手调整级别，还是续期只沿用上次配置、调整必须另走「调整授权」；
- 虚拟机动作配额耗尽时，总状态显示「已授权但配额用尽」，还是直接归入「需要续期」；
- 多个旧票据同时生效时，状态卡是全部列出，还是只列与当前目标匹配的那一张。
